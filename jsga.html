Overview

The Jain Society of Greater Atlanta needed one place to handle what used to be spread across forms and spreadsheets: renewing memberships, taking donations for different funds, sending proforma invoices, and running community services for its members.

I work on this platform as part of a five-person team at Datagrid Solutions, using Laravel 11 and MySQL. The parts below are the ones I built.

  • Member IDs and linked family members

  • Donation tracking, invoices and a donation dashboard
  • "Scan to Donate" QR code for each fund

  • Proforma invoices for members and non-members

Problems I solved

  1. 01

    A deleted proforma crashed every payment list

    Problem. Payment history read the event details from the proforma a payment came from, without checking that the proforma still existed. One payment whose proforma had been deleted made the whole list fail, for every user opening it: member, vendor and the "All Payments" report. Four live transactions were affected.

    What I did. I found every place that read from that proforma (the three payment lists and the invoice) and made each one handle a missing proforma, so that one payment shows without those details instead of breaking the page for everyone.

  2. 02

    The donation dashboard failed on QA with no clear reason

    Problem. On the QA server the donation dashboard only said "Failed to load dashboard data". The generic message hid the real error, and the dashboard worked on other machines.

    What I did. I briefly let the error response show the underlying exception to trace it: the dashboard query used two payment columns whose migration had never been committed, so any server where it had not been run by hand was missing them. I added the migration and then removed the temporary debug output.
